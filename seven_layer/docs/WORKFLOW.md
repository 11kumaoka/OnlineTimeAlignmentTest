# Workflow: from simulation to SiMAPS alignment parameters

**Source baseline:** [`seven-layer-alignment` / `21008ae`](https://github.com/11kumaoka/OnlineTimeAlignmentTest/tree/21008aedd46ae28123728fb4606213865b7a3b9e).\
**Audience:** Collaborators wishing to reproduce the local beam-test telescope prototype.\
**Scope:** 5-GeV μ⁻ simulation; local SiMAPS/MPGD/AC-LGAD digitization and reconstruction; ACTS track fitting; **five-SiMAPS x/y translation bias fitting with Millepede-II**. This does **not** perform spatial-correction application, geometry closure or timing calibration.

## Reproducibility warning

A **previously prepared development workspace** was used for the reported end-to-end tests. A fresh Git clone is **not yet sufficient** for a turnkey run because:

1. Official Mille/Millepede-II source and compiled installation are excluded from Git and there is no complete external-dependency installer in the committed scripts.
2. `run_integrated_mille_baseline.sh` and `run_integrated_mille_injected.sh` hard-code input `seven_layer/results/phase2_sim_quick_normal_recofix.edm4hep.root`, which is not tracked or generated by a committed script with that exact filename.
3. `eicweb/eic_xl:nightly` is a moving image tag; the current scripts also hard-code one `thisepic.sh` installation path.
4. The script `seven_layer/scripts/run_phase2_reconstruction.sh` is an **earlier full-ePIC CKF experiment**, not the current validated local plugin workflow; at least its second Docker invocation fails to forward `COLLECTIONS` while using `set -u`. Do not promote it as a verified end-to-end entry point.

The following commands distinguish **committed/tested development entry points** from **proposed fresh-checkout preparation**. The latter require clean-environment testing.

## 1. Checkout and workspace

Host machine with Docker running:

```bash
git clone --branch seven-layer-alignment https://github.com/11kumaoka/OnlineTimeAlignmentTest.git
cd OnlineTimeAlignmentTest
mkdir -p seven_layer/results seven_layer/logs seven_layer/millepede/results/integrated
```

All paths below are relative to repository root. The scripts mount this directory as `/work` inside the `eicweb/eic_xl:nightly` container, with `--platform linux/amd64`.

## 2. Geometry and initial simulation (committed entry point)

```bash
bash seven_layer/scripts/run_phase1_ddsim.sh
```

This script invokes `ddsim` to produce:

| File | Meaning |
| --- | --- |
| `seven_layer/results/sim_seven_layer_single.edm4hep.root` | One straight-through 5-GeV μ⁻ |
| `seven_layer/results/sim_seven_layer_beam.edm4hep.root` | 200-event low-angular-spread μ⁻ sample |
| `seven_layer/results/phase1_hits_*_summary.json` | Sim hit/layer summaries |
| `seven_layer/results/seven_layer_telescope.gdml` | GDML export for overlap checking |
| `seven_layer/results/phase1_overlap_summary.json` | Geometry overlap diagnostics |
| `seven_layer/results/seven_layer_layout.png` | Layout drawing based on metadata JSON |

See [`seven_layer/scripts/run_phase1_ddsim.sh`](../scripts/run_phase1_ddsim.sh). The 200-event beam here uses θ = 0–3 mrad, **not** the later 10–30 mrad Phase-2 sample.

Seven nominal planes: SiMAPS layers 0–4 at 0, 50, 100, 150, 200 mm; MPGD layer 5 at 250 mm; AC-LGAD layer 6 at 300 mm. Read the **actual DD4hep XML** (`../geometry/seven_layer_telescope.xml`) for authoritative runtime geometry/readout, rather than assuming the metadata JSON is always synchronized.

## 3. Input for the current integrated alignment workflow (not yet automated)

The current baseline/injected scripts expect:

```text
seven_layer/results/phase2_sim_quick_normal_recofix.edm4hep.root
```

This ROOT file is **not distributed in Git** and the exact previous generation command is not in a committed script. Do not rename the Phase-1 sample and claim to reproduce the original numerical test. To generate an *analogous* μ⁻ sample with the **10–30 mrad** beam settings documented in `run_phase2_reconstruction.sh`, a candidate command is:

```bash
docker run --rm --platform linux/amd64 \
  -v "$PWD:/work" -w /work eicweb/eic_xl:nightly bash -lc '
    set -euo pipefail
    ddsim \
      --compactFile seven_layer/geometry/seven_layer_telescope.xml \
      --outputFile seven_layer/results/phase2_sim_quick_normal_recofix.edm4hep.root \
      --numberOfEvents 80 \
      --enableGun \
      --gun.particle mu- \
      --gun.energy "5*GeV" \
      --gun.thetaMin 0.010 --gun.thetaMax 0.030 \
      --gun.phiMin 0.0 --gun.phiMax 6.283185307179586 \
      --gun.distribution uniform \
      --vertexSigma 0.2 0.2 0.0 0.0
  '
```

**Classification: proposed / unverified in a fresh checkout.** It uses options found in the committed Phase-2 script, with a changed output name and event count to satisfy the current integration scripts. Event content, acceptance, and solver results are not guaranteed to reproduce the previously reported numbers without matching the original simulation seed and configuration. Check that the ROOT file and expected `SiMAPSHits`, `MPGDHits`, `ACLGADHits` collections were created before proceeding.

## 4. External Mille and Millepede-II installation (manual prerequisite)

Upstream repositories:

- Mille C++ library: https://gitlab.desy.de/millepede/Mille
- Millepede-II and `pede`: https://gitlab.desy.de/millepede/millepede-ii

The local installation expected by the committed CMake and run scripts is **`seven_layer/millepede/install/millepede-ii`**. Verify that:

- CMake can locate a `MilleConfig.cmake` providing `Mille2` in that prefix;
- `seven_layer/millepede/install/millepede-ii/bin/pede` exists and is executable **inside the Docker container**;
- `seven_layer/millepede/install/millepede-ii/lib` contains the needed shared libraries.

The project's `build_mille_tools.sh` does **not** download/build/install these upstream dependencies. Follow the upstream build instructions and the prior integration notes in [`../millepede/reports/millepede_progress_report.md`](../millepede/reports/millepede_progress_report.md). Record and pin the dependency commits for reproducibility. A verified bootstrap installer is an outstanding project task.

## 5. Build the local BeamTestReco plugin (development command from scripts)

After the upstream Mille installation exists, from the repo root:

```bash
docker run --rm --platform linux/amd64 \
  -v "$PWD:/work" -w /work eicweb/eic_xl:nightly bash -lc '
    set -euo pipefail
    source /opt/software/linux-x86_64_v2/epic-26.05.0-2ixc5forg4ihbpragwu2m6422njxulk3/bin/thisepic.sh
    cmake -S seven_layer/local_eicrecon -B seven_layer/local_eicrecon/build \
      -DCMAKE_BUILD_TYPE=RelWithDebInfo \
      -DENABLE_MILLEPEDE=ON \
      -DMILLEPEDE_PREFIX=/work/seven_layer/millepede/install/millepede-ii
    cmake --build seven_layer/local_eicrecon/build -j
  '
```

Expected build product: `seven_layer/local_eicrecon/build/BeamTestReco.so`. If CMake cannot find Mille, go back to Step 4; the local plugin is built with Mille enabled by default.

## 6. Integrated digitization, reconstruction, ACTS and Mille binary

**This is the current primary local workflow, not the legacy default ePIC CKF test.** After Steps 3–5:

```bash
bash seven_layer/millepede/scripts/run_integrated_mille_baseline.sh
```

The script starts `eicrecon` with the local `BeamTestReco` plugin and ignores incompatible standard ePIC detector plugins. Inside the same JANA2 process it performs:

- `SiMAPSHits / MPGDHits / ACLGADHits` → provisional local digitization;
- local raw hits → normal reconstruction without MC-associated position truth;
- telescope-specific ACTS track fitting (SiMAPS and, by default, MPGD; AC-LGAD not fitted);
- EDM4eic ROOT output and Mille binary writing.

Outputs:

```text
seven_layer/results/local_simaps_reco_mille_integrated.root
seven_layer/millepede/results/integrated/local_beamtest_mille_integrated.dat
seven_layer/logs/local_eicrecon_runtime_mille_integrated.log
```

The **script removes and replaces its named ROOT and `.dat` outputs** on every run. Preserve important previous results under a different name. Its input path is currently fixed and its event count is 80.

For the post-audit dataset, the validation report gives **80 events / 68 accepted tracks / 68 records / 680 measured coordinates**; a fresh simulated sample can differ. Inspect the `BeamTestMilleProcessor::Finish` counters and ACTS `fit_skip` messages in the log, and do not confuse the acceptance fraction with tracking efficiency.

## 7. Solve global alignment parameters with actual `pede`

```bash
bash seven_layer/millepede/scripts/run_pede_from_dat.sh \
  seven_layer/millepede/results/integrated/local_beamtest_mille_integrated.dat \
  baseline
```

Result files (relative to repo root):

```text
seven_layer/millepede/results/integrated/baseline_pede.txt
seven_layer/millepede/results/integrated/baseline_pede.log
seven_layer/millepede/results/integrated/baseline_millepede.res
seven_layer/millepede/results/integrated/baseline_millepede.log
```

The alignment equation used by `BeamTestMilleWriter.cc` is

\[
 x_i = x_0 + t_x(z_i-z_{\mathrm{ref}}) + a_{x,i} + \epsilon_{x,i}, \qquad
 y_i = y_0 + t_y(z_i-z_{\mathrm{ref}}) + a_{y,i} + \epsilon_{y,i}.
\]

`zref = 100 mm`. Global label `1000+i` denotes x bias and `2000+i` denotes y bias for layer i. SiMAPS L0 and L4 are held fixed; intermediate layers L1–L3 are solved. **Correction of measured positions would be `-a`**, but applying such corrections is **not part of this version**.

## 8. Controlled measurement-injection closure

```bash
INJ_LAYER=2 INJ_X_MM=0.2 INJ_Y_MM=0.0 \
  bash seven_layer/millepede/scripts/run_integrated_mille_injected.sh

bash seven_layer/millepede/scripts/run_pede_from_dat.sh \
  seven_layer/millepede/results/integrated/local_beamtest_mille_integrated_milleInjL2x0.2.dat \
  injected_L2x0p2

python3 seven_layer/millepede/scripts/summarize_pede_res.py \
  --baseline seven_layer/millepede/results/integrated/baseline_millepede.res \
  --comparison seven_layer/millepede/results/integrated/injected_L2x0p2_millepede.res
```

The injection is **only in the Mille measurement-writing stage**, not a mechanical displacement in DD4hep, and it does **not** modify the ACTS input hit collection. The previous post-audit sample gave Δ(label 1002) ≈ +0.20000413 mm for +0.200 mm injected. New random samples will have different absolute baseline parameters.

## 9. Optional toy experiment

The toy program and official `pede` can test the alignment model without EICrecon. Once Step 4 is fulfilled, the committed tools may be built/executed **inside the same compatible Linux Docker environment**:

```bash
docker run --rm --platform linux/amd64 \
  -v "$PWD:/work" -w /work eicweb/eic_xl:nightly bash -lc '
    set -euo pipefail
    export LD_LIBRARY_PATH=/work/seven_layer/millepede/install/millepede-ii/lib:${LD_LIBRARY_PATH:-}
    bash seven_layer/millepede/scripts/build_mille_tools.sh
    bash seven_layer/millepede/scripts/run_toy_closure.sh
  '
```

The toy wrapper itself does not start Docker; running Linux binaries built inside Docker directly on macOS will not work. The command above is an **environment-compatible proposed invocation**, not a freshly tested clean-clone transcript.

## 10. What does *not* work yet

- No verified `setup_dependencies.sh` or clean-clone continuous integration that builds the official Mille library and `pede`.
- No automatic generation of the current primary integration script's exact input filename from the established simulation script.
- No fixed digest for the Docker image or complete provenance for third-party build commits.
- No application of solved alignment parameters to the reconstructed hit positions or DD4hep geometry.
- No final detector-geometry/rotation closure; no time calibration.
- No general multi-track/ambiguous-hit finder; current fitter can skip events with multiple hits, **including MPGD ambiguity** when `useMPGD=true`.
- MPGD / AC-LGAD digitization is provisional, and ACTS→EDM4eic semantics need further review.
